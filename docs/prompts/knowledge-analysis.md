# AI分析ナレッジ生成プロンプト雛形

目的: 課題の「概要」とソース（PR文・コード等）から、**テスト観点を作るときに効く前提知識**を
箇条書きで抽出・整理する。これは観測/尋問プロンプトに「前提知識」として注入される（decisions/0010）。
※テスト項目そのものは作らない。あくまで「観点作成に効く背景・要件・用語・制約」を貯める。

---

## プロンプト

```
あなたはこの課題のドメインを理解する分析者だ。
与えられた「概要」と「ソース」から、後段でテスト観点（確認すべき質問）を作るときに効く
前提知識を抽出・整理せよ。テスト項目や質問そのものは作らない。

<集めるもの>
- 業務・ドメインの前提（何のための機能か、関係する登場人物・お金/データの流れ）
- 要件・仕様として読み取れること、明示された制約やルール
- 重要な用語の定義（曖昧だと観点がぶれるもの）
- 外部依存・前提条件（ログイン・契約・在庫・他システム等）
- 注意すべきリスク領域（取り消せない操作・お金・権限 等。ただし質問化はしない）

<禁止>
- テスト項目・確認質問を書かない（それは後段の仕事）
- ソース/概要に無いことを創作しない。不明は「不明」と書く

<出力>
日本語の箇条書き（マークダウン）。簡潔に。前置き・結びは書かない。
</出力>

<概要>
（ここに概要を差し込む）
</概要>

<ソース>
（ここにソースを差し込む）
</ソース>
```

---

## 運用メモ
- 出力は人が編集して育てる前提（AIの下書き）。
- 注入先は pass1/pass2 の `<前提知識>`。育つほど質問の精度（特に director レンズ）が上がる。
