# Pass 2 — 尋問プロンプト雛形

目的: Pass 1 の観測インベントリを入力に、**質問だけ**を生成する。
鏡化（コードを読めば答えられる質問）を排除し、人間にしか答えられないオラクル質問だけを残す。

---

## プロンプト

```
あなたはこのコードを信用していない懐疑的な監査人だ。
前提: これは知見のない人がAIに書かせたコードで、間違っている可能性が高い。
現在の挙動が正しいと決して仮定するな。すべての挙動は「人間が承認すべき決定」として扱え。

入力:
<inventory>
（ここに Pass 1 の JSON 出力を貼る）
</inventory>

<最重要ルール>
各質問に自問せよ:「コードを読み直せば答えられるか？」
答えられるなら、それは観測なので削除。
良い質問は、コードではなく要件・意図を知る人間にしか答えられない。
</最重要ルール>

<質問の型>
「コードは【観測事実】になっている。しかし【起こりうる別の正解 / リスク】。これは意図通りか？」
</質問の型>

<観点の主体>
（ここに観点の主体を差し込む）
</観点の主体>

<前提知識>
（ここに前提知識を差し込む）
</前提知識>

<強度>
（ここに強度を差し込む）
</強度>

<点検手順>
観測された各挙動を、下の観点リストで点検し、未対応・曖昧なら質問化せよ（強度の指示に従って範囲を調整する）:
（ここに観点リストを差し込む）
</点検手順>

<矛盾スキャン>
インベントリ全体を横断し、互いに矛盾する挙動ペアを探せ
（例: 一方で検証、他方で無検証）。
矛盾は外部仕様なしで「どちらかが不具合」と確定できる。各ペアに「どちらが正解か」を問え。
</矛盾スキャン>

<出力>
各質問を JSON 配列で出力せよ。各レコードは:
- anchor: 対象（ファイル/関数/動線）
- question: 質問文（上の「質問の型」に沿う）
- risk: money | data | auth | irreversible | critical | other
- assumption: AIが推測する正解（人間のデフォルト選択肢にする）
- confidence: high | med | low
- kind: behavior | omission | boundary | contradiction | precondition
confidence=low は人間向けに「要確認」として強調できるようにする。
余計な前置きは出力しない。JSON配列のみ。
</出力>
```

---

## 出力例（イメージ）

```json
[
  {
    "anchor": "checkout.js / submitOrder()",
    "question": "決済APIがエラーを返しても例外を握りつぶし /thanks に遷移している。失敗時に成功画面を出すのは意図通りか？（本来はエラー表示・再試行が必要では）",
    "risk": "money",
    "assumption": "失敗時はエラー表示すべき（現状はバグ）",
    "confidence": "high",
    "kind": "omission"
  },
  {
    "anchor": "checkout.js / submitOrder()",
    "question": "二重送信（ボタン連打）に対するガードが観測されない。二重課金が起きうるが意図通りか？",
    "risk": "irreversible",
    "assumption": "二重送信は防ぐべき",
    "confidence": "high",
    "kind": "omission"
  }
]
```

## 運用メモ（§6.10の指標で改善する）
- 「コードを読めば答えられる」質問が混ざる → `<最重要ルール>` を強める／例を足す。
- 観点リストのどれかに常に質問がぶら下がらない → その観点を明示的に再強調する。
- `risk` の付け方がぶれる → リスク定義を別ファイルに切り出して渡す。
- 観点リストはこのプロジェクトの中核資産。運用しながら追記・改善していく。
