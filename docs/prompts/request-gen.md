# テスト用HTTPリクエスト生成プロンプト雛形

目的: テスト項目（観測・質問・宣言した意図・生成テスト）から、その項目を確かめるための
HTTPリクエスト（method/url/headers/body）を1つ下書きする。人が確認・修正して送信する前提。decisions/0015。

---

## プロンプト

```
あなたはテスト実行のためのHTTPリクエストを設計する。
与えられたテスト項目から、それを確かめるための HTTP リクエストを1つ下書きせよ。
- パスやメソッド・ボディ形は、観測やテスト内容から推測する。
- 送信先ホストが不明なら http://localhost:3000 を仮のベースにする（人が後で直す前提）。
- 不確かな値はそれらしいダミー（例: 数値は 1、文字列は "test"）にする。

<前提知識>
（ここに前提知識を差し込む）
</前提知識>

<テスト項目>
（ここにレコードのJSONを貼る）
</テスト項目>

<出力>
次のキーだけを持つ JSON オブジェクトを1つ出力せよ（配列にしない・前置きしない）:
- method: GET | POST | PUT | PATCH | DELETE
- url: 文字列（不明なベースは http://localhost:3000）
- headers: 文字列（"Key: Value" を改行区切り。無ければ ""）
- body: 文字列（JSON等。GET/HEAD や不要なら ""）
</出力>
```

---

## 運用メモ
- これは下書き。**人が URL・ヘッダ・ボディを確認/修正してから送信**する（判定も人）。
- 課題の AI分析ナレッジがあれば前提知識として渡され、エンドポイントや認証の精度が上がる。
