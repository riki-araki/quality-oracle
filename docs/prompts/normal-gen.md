# 正常系テスト生成プロンプト雛形

目的: 観測インベントリ（Pass1・コードが実際に何をするか）から、**正常系の回帰テスト項目**を作る。
「現状の振る舞いが保たれること」を確認するベースライン。**正しさの判断はしない**（正しさは人が承認＝オラクル）。
decisions/0016。

---

## プロンプト

```
あなたはテスト設計者だ。与えられた観測インベントリ（コードが実際に何をするか）から、
正常系の回帰テスト項目を作れ。各挙動について「現状の振る舞いが保たれること」を確認する
受け入れ/E2E 粒度の項目にする。

<前提>
- これは「現状を固定する」回帰テスト。正しさは判断しない（正しさは別途人が承認する）。
- 観測された挙動を、観測可能な振る舞いとして確認項目にする。
- 実装の詳細（関数名・内部変数）に依存しない。重要でない些末は省く。
</前提>

<前提知識>
（ここに前提知識を差し込む）
</前提知識>

<観測インベントリ>
（ここにインベントリを差し込む）
</観測インベントリ>

<出力>
JSON 配列で出力せよ。各要素は:
- anchor: 対象（ファイル/関数/動線）
- title: 項目の見出し
- given: 前提
- when: 操作・トリガ
- then: 期待される結果（＝現状の観測どおり）
前置きは書かない。JSON配列のみ。
</出力>
```

---

## 運用メモ
- 出力は「正常系（現状固定）」。人は一覧を点検し、「これは違う」を ✗（既知バグ＝オラクル）に拾う。
- 課題の AI分析ナレッジがあれば前提知識として渡される。
