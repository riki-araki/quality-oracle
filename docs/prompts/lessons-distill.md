# 訂正の資産化（学習ナレッジ抽出）プロンプト雛形

目的: このプロジェクトで人が下した **✗訂正**（観測された挙動 → 人が示した「正しい意図」）の履歴から、
**繰り返し現れる教訓・落とし穴・チーム固有の意図**を、再利用可能な前提知識として抽出する。
出力は配下すべての観測/尋問の `<前提知識>` に注入され、「使うほど質問が賢くなる」土台になる（decisions/0023）。
※テスト項目や確認質問そのものは作らない。あくまで「次の観点作成に効く教訓」を貯める。

---

## プロンプト

```
あなたはこのプロジェクトの品質の番人だ。過去に人間が下した「✗訂正」の一覧を渡す。
各訂正は「AIが観測した挙動（observation）」と「人が示した正しい意図（correctedIntent）」の対で、
＝『コードはこう動いていたが、本当はこうあるべきだった』という、このチーム固有の判断の記録だ。

これらを横断し、**繰り返し現れる教訓・落とし穴・暗黙のルール**を抽出して、
次に別のコードを観測するときに効く「前提知識（教訓）」としてまとめよ。

<抽出するもの>
- 何度も訂正されている共通パターン（例: 「この種の入力は必ず境界を確認」「金額は税込で扱う」等）
- このチーム固有の暗黙のルール・用語・意図（コードだけからは読み取れないもの）
- 繰り返し見落とされているリスク領域（お金・権限・取り消せない操作 等）

<禁止>
- 個別の1件をそのまま書き写さない。**一般化された教訓**にする（1回限りの事情は省く）。
- テスト項目・確認質問を書かない（それは後段の仕事）。
- 渡された訂正に無いことを創作しない。

<出力>
日本語の箇条書き（マークダウン）。各項目は「教訓」＋必要なら短い根拠。簡潔に。前置き・結びは書かない。
教訓が見当たらなければ「（繰り返しパターンは見当たらない）」とだけ書く。
</出力>

<訂正の履歴>
（ここに訂正履歴を差し込む）
</訂正の履歴>
```

---

## 運用メモ
- 入力は「adopted かつ status=corrected」のレコード（observation → declaredIntent）。プロジェクト配下の全課題を横断。
- 出力は人が編集して育てる前提（AIの下書き）。注入先は pass1/pass2 の `<前提知識>`（課題ナレッジと併記）。
- ✗訂正は人の判断由来なので、AI推測より格段に高信頼。これがツールの「使うほど強くなる」堀（moat）になる。
