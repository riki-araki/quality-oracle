# 0007. 観点の主体（ディレクター/エンジニア）と強度（緩/中/強）のレンズを導入

- 日付: 2026-06-28
- ステータス: 採用

## 背景 / 何を決めるか
生成質問が「エンジニアに寄りすぎ・観点が細かすぎる」という指摘。原因は Pass1 がコードを観測するため
技術の縁ケースに偏ること。これを直しつつ、提案された「主体／強度／粒度」の3軸を整理して決める。

## 決定
3軸を分けて扱い、今回は **主体（Perspective）と強度（Intensity）** を実装する：
1. **Perspective**: `director`（業務/画面/ビジネスルール）/ `engineer`（実装/技術）。
   観測と質問の「高度」を変える。director はユーザー/業務の言葉で問い、技術詳細に踏み込まない。
2. **Intensity**: `loose`（最重要リスクだけ）/ `medium` / `strong`（観点を総当たり）。「細かすぎ」を調整する。
3. **Level（単体/結合/総合）は今回やらない**。受け入れ/総合(E2E)を既定とし、単体/結合は保留（§5.2 の北極星のまま）。
   理由は下記。

実装：
- レンズ定義は `docs/prompts/lenses.md` に単一の真実源として置き（`<!-- BLOCK key -->` で抽出）、
  Pass1/Pass2 の雛形へ注入。プロンプト文字列をコードに二重持ちしない。
- run/record に `perspective` / `intensity` をタグ付け（既存DBは ALTER で migrate、既定 engineer/strong）。
- CLI: `oracle run --lens director|engineer --intensity loose|medium|strong`（既定 engineer/strong）。
- ダッシュボード: 課題ヘッダ・項目詳細に主体/強度バッジを表示。

## 理由
- **director レンズは核（§2「意図を知る人間＝多くは責任者/ディレクター」、§6「人間がオラクル」）に忠実**。
  買い手（困っている責任者）に刺さり、差別化を深める。検証でも質問が業務目線に変わり、件数も適正化した
  （checkout.js: engineer/strong 16問 → director/loose 6問、すべて money/critical/data）。
- 単体/結合は **§5.2 と衝突**し、かつ**より技術寄り**で「エンジニア偏重を直したい」という当の不満と逆行する。
  痛みは主体/強度で解けるため、Level の拡張は核の検証後に独立判断とする。

## 捨てた選択肢とその理由
- **単体/結合を今すぐ解禁**: §5.2 を覆す大きな賭け。不満と逆方向。保留。
- **主体ごとに別プロンプトファイルを量産**: 二重管理になる。lenses.md の block 注入で単一の真実源を保つ。
- **既定を director/loose にする**: 既存挙動が変わり驚く。既定は engineer/strong（従来同等）にし、明示で切替。

## 影響・前提（後で覆すとき確認すべきこと）
- 観点リスト（§6.5）は主体ごとに分岐した。中核資産なので運用で育てる（lenses.md）。
- 次スライス: 一覧の「＋項目追加」（対象＋主体＋強度を選び観測→候補をピックアップ）と
  プロジェクト直下の横断ダッシュボード（主体別/強度別/状態別の可視化）。前者は UI からの観測起動の解禁が要る。
- Level（単体/結合/総合）を将来入れるなら、本決定の「粒度」軸として別 decision を起こす。
