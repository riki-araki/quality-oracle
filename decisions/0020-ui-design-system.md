# 0020. UIデザインシステム（Vercel/Geist 方向・テーマトークン・共通プリミティブ）

- 日付: 2026-06-30
- ステータス: 採用

## 背景 / 何を決めるか
- 画面を増やすうちにスタイルが各所でアドホックになり、見た目の一貫性が崩れがちだった。
- ユーザーの希望で**有名サービス（Vercel）水準の「モダン/クリーン」**を目指すと決定。
- 「画面のマネ」ではなく**下のデザインシステム（型・余白・抑制・反応性）を借りる**方針を固定する。

## 決定（デザイン言語）
1. **方向＝Vercel/Geist**：白基調（ライト #fafafa / パネル白）・純黒（ダーク #000）・**ハイラインのボーダー**・
   アクセント＝**Vercel ブルー `#0070f3`**。影は控えめでフラット（ボーダー主体）、角丸は控えめ（ボタン/入力 6px）。
2. **フォント＝Geist**（`geist` パッケージ・同梱フォントで外部取得なし）。本文 Geist Sans / 等幅 Geist Mono。
3. **テーマトークン化（ライト/ダーク切替）**：色は全て CSS 変数。`:root`=ライト / `.dark`=ダークで上書きし、
   Tailwind v4 `@theme inline` でユーティリティに反映。**hex 直書き禁止**（例外は Excel 出力の ARGB）。
   切替は `app/lib/theme-toggle.tsx`（html の `.dark`＋localStorage）、FOUC 防止は `layout.tsx` の inline script。
4. **アイコンは絵文字をやめ統一ラインアイコン**（`app/lib/icons.tsx`・Lucide のパス内蔵・依存なし）。
   ※ファイル名は Next 予約の `icon` と衝突するため `icons.tsx`。ファビコンは `app/icon.svg`、ブランドは `app/lib/logo.tsx`。
5. **色の抑制**：色は「状態（結果/優先度/既知バグ）」に限定。種別/リスク/正常系などメタ情報はニュートラル。
6. **共通プリミティブ（単一の真実源）**：
   - クラス: `card` / `glass` / `btn-primary` / `btn-ghost` / `field` / `select` / `chip` / `divider` / `skeleton`（globals.css）。
   - 部品: `PageHeader`・`EmptyState`・`Avatar`（名前ベース配色）・`ResultBadge`・`Markdown`・`Toaster`/`toast()`・
     `SubmitButton`（保留表示）・`CommandPalette`（⌘K 横断検索）・`Logo` 等（`app/lib/`）。

## 理由
- 一貫したトークン＋共通部品にすると、新画面でも自動的に質感が揃い、テーマ追従も無料で付く。
- Geist/ブルー/ライン アイコンは「素のアプリ感」を消す効き目が大きい（知覚品質の底上げ）。

## 捨てた選択肢とその理由
- **特定画面のスクショを模倣**：再現性が低く崩れやすい。トークン/原則を借りる方が堅い。
- **絵文字アイコン継続**：手作り感が出る。統一ストロークに置換。
- **多色のピル多用**：情報の優先順位がぼやける。色は状態に限定。
- **next/font/google（Inter 等の都度取得）**：ビルド時ネットワーク依存。同梱フォントの Geist にした。

## 影響・前提（後で覆すとき確認すべきこと）
- 色を足す時は必ず globals.css のトークン（`:root`/`.dark`）に追加し、ユーティリティ or `var(--…)` で使う。
- ロゴ/アクセント色はブランド確定時に差し替え可能（トークン1か所）。
- ホスト型 SaaS 化（decisions/0002・0018 Phase3）でもこの言語をそのまま使う。
