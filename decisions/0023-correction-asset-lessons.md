# 0023. 訂正の資産化（✗訂正から学習ナレッジを抽出し観測に注入）

- 日付: 2026-07-01
- ステータス: 採用

## 背景 / 何を決めるか
- 人が積む **✗訂正**（観測された挙動 → 人が示した正しい意図）は、このチーム固有の意図・落とし穴が詰まった
  最高信頼のデータだ（AI推測ではなく人の判断由来）。だが現状は各項目に埋もれて**死蔵**され、次の観測に活きていない。
- **②訂正の資産化**を実装する（3案の2番手）。繰り返される訂正を再利用可能な「教訓」に蒸留し、
  以後の観測/尋問の `<前提知識>` に自動注入する。「使うほど質問が賢くなる」堀（moat）を作る。

## 決定
1. **抽出（AI・下書き）**：`distillLessons` が、プロジェクト配下の corrected レコード（observation → declaredIntent）を
   横断し、繰り返しの教訓・暗黙のルール・見落としがちなリスク領域を箇条書きに蒸留する。プロンプトは
   `docs/prompts/lessons-distill.md`（単一真実源。「1件の書き写しでなく一般化」「テスト項目は作らない」を明記）。
2. **保存先＝プロジェクト**：`project_meta.lessons`（冪等 ALTER・非破壊）。課題（issue.knowledge）より広い単位で、
   チームの学習をプロジェクト全体で共有する。`upsertProject` は lessons を触らず保持（`setProjectLessons` で更新）。
3. **注入（自動）**：`loadKnowledge(ledger, issueId)` が **プロジェクトの学習ナレッジ ＋ 課題の AI分析ナレッジ** を結合し、
   観測(Pass1)/尋問(Pass2)/正常系/ドリフト検査すべての `<前提知識>` に渡す。プロンプト雛形は変更不要（既存の注入経路に相乗り）。
4. **人が制御できる**：出力は AIの下書きで、`/project` の「学習ナレッジ（訂正から）」パネルで Markdown 表示・
   「訂正から教訓を抽出」ボタン・手編集ができる（owner/member/admin）。核（正しさは人が決める）と整合：教訓は人の訂正由来で、
   さらに人が編集して育てる。
5. **AI使用量に計上**：抽出呼び出しは `AiUsageKind="lessons"` として ledger.ai_usage に記録（decisions/0021 に整合）。

## スコープ規律との整合
- 既存のナレッジ注入経路（decisions/0010）に相乗りする最小実装（1列＋1パネル＋1プロンプト＋2アクション＋結合関数）。
- 新しい外部連携や自動テスト実行ではない（ガードレール非抵触）。自動での本注入前に人がレビュー/編集できる。

## 捨てた選択肢
- **個別訂正をそのまま注入**：ノイズが多く、量が増えるとプロンプトが膨れる。→ 一般化した教訓に蒸留。
- **教訓を1件ずつDBに正規化してキュレーション**：過剰。まずは編集可能な1テキストで十分（育ってから分割を検討）。
- **グローバル（組織横断）に共有**：プロジェクトごとに文脈が違う。まずプロジェクト単位（decisions/0018 の分離に整合）。
