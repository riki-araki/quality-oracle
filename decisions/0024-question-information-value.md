# 0024. 質問の情報量で並べる（当たりそうな順・鏡の抑制・レンズ較正）

- 日付: 2026-07-01
- ステータス: 採用

## 背景 / 何を決めるか
- ✓スルー（§6.7）はこのツールの生命線を脅かす最大の弱点。人の承認予算は有限なので、
  **当たりそうな質問（AIが不確か・矛盾/抜け・高リスク）を上に**、**鏡に近い低情報（AIが高確信・単なる挙動・低リスク）を下げる**。
- あわせて **どの主体×強度（レンズ）が実際に問題を捕まえたか**を実データで可視化し、既定の選び方を較正する（③案）。
- LLM 追加呼び出しは無し（既存の記録から計算するだけ）＝コスト増なし・ガードレール非抵触。

## 決定
1. **情報量スコア（`infoScore`）**：`confidence`（low+3/med+1/high+0）＋ `kind`（contradiction+3/omission+2/precondition+2/
   boundary+1/behavior+0）＋ `risk`（money/auth/irreversible/critical+2・data+1）。高いほど人が見るべき。
2. **鏡に近い低情報（`isLowInfo`）**：`confidence=high` かつ `kind=behavior` かつ 高リスクでない候補。
   ＝コードの言い換えに近く、承認予算をかける価値が低い。
3. **候補レビュー（/add）の並べ替え**：オラクル質問を **highInfo（当たりそうな順・`sortByInfo`）→ 非オラクル候補 →
   lowInfo（畳んだ「低情報」グループ・淡色表示）** に再構成。種別チップ（矛盾/抜け/前提/境界/挙動）で「なぜ上か」を示す。
   ※§6.3 アンチミラーは「質問」に効かせる原則（decisions/0016）と整合：低情報＝鏡に近い質問を下げる。
4. **レンズ別の当たり率（/project）**：オラクル記録を主体×強度で集計し、**当たり率＝(corrected+unknown)/decided** を
   降順表示（生成数・捕捉/判定つき）。「効くレンズ」を実データで見せ、観測時の既定選びの材料にする（読み取り専用）。

## スコープ規律との整合
- 純粋な並べ替え＋集計。新しい外部連携・自動実行・LLM追加呼び出しは無い。
- 候補の削除や自動判定はしない（低情報は「畳む」だけで捨てない。判断は人）。

## 捨てた選択肢
- **LLMで各質問の情報量を採点**：コストと循環（AIが自分の質問を採点）を招く。→ 観測メタ（confidence/kind/risk）から機械的に算出。
- **低情報を自動で捨てる/非表示**：見落としリスク。→ 畳んで下げるに留め、人がいつでも開ける。
- **レンズ較正を自動で既定へ反映**：まだ根拠が弱い。→ まず可視化。既定の自動調整は運用で効果が見えてから。
