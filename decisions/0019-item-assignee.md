# 0019. テスト項目に担当者(assignee)を追加

- 日付: 2026-06-29
- ステータス: 採用

## 背景 / 何を決めるか
- 複数人で手動テストを分担する（design.md §7「エンジニア数名で分担して手動テスト」）ために、
  **「この項目は誰が試験するか」= 担当者**を項目に持たせたい。
- 既存の `results.created_by`（実施者＝結果を記録した人。decisions/0018）とは別概念：
  **担当者＝割り当て（これからやる人）／実施者＝実際に記録した人**。

## 決定
1. `records.assignee`（userId・nullable）を追加。既定は未割当（null）。
2. **割り当て可能な相手はプロジェクトのメンバー**（decisions/0018 のメンバーシップ）。項目詳細の右レールで変更。
3. 一覧（ItemsTable）に **担当列**を表示し、**「自分の担当だけ」フィルタ**を用意（テスターが自分の分を抽出）。
4. 編集は `canEdit`（member 以上）。viewer は不可。

## 理由
- 分担の最小単位は「項目に担当者」。プロジェクト/課題単位より粒度が要る（人によって担当項目が混在するため）。
- 実施者(created_by)と分けるのは、**予定（担当）と実績（実施）を別に追える**ようにするため。

## 捨てた選択肢とその理由
- **担当を課題単位だけにする**: 課題内で人を分けられない。項目単位にする。
- **任意の全ユーザーを担当に**: アクセス権のない人を割り当てるのは不整合。**プロジェクトメンバーに限定**。
- **複数担当（配列）**: 当面オーバースペック。単一担当で始める。

## 影響・前提（後で覆すとき確認すべきこと）
- `records.assignee TEXT`（nullable）を追加（冪等 ALTER・既存行は null＝未割当）。**非破壊**。
- 担当者がプロジェクトから外れても assignee の userId は残る（表示名が引けない場合は ID 表示にフォールバック）。
