# 0014. 項目に手動HTTPコンソール（Postman風）。人が送り人が判定

- 日付: 2026-06-28
- ステータス: 採用

## 背景 / 何を決めるか
「curl で正誤を確かめられる観点」は、項目内でリクエストを組み立てて送信し、結果を記録したい。
ただし CLAUDE.md「テスト実行機能は作らない」に触れるため、線引きを決める。

## 決定
1. **手動HTTPコンソール**をテスト項目に組み込む：メソッド/URL/ヘッダ/ボディを保存し、[送信]で
   **サーバ側から実行**してレスポンス（ステータス/所要時間/本文）を表示する。
   - **合否は人が判定**し、既存の「実行結果」（0009）に pass/fail で記録する。**自動判定はしない**。
2. **証跡の棲み分け**：
   - 画面/UIの確認 → **スクリーンショット**（画像証跡・0006）。
   - API/リクエスト系 → **送受信そのものが証跡**。「この送受信を証跡に保存」で**テキスト証跡**として保存でき、
     証跡一覧に画像と並んで載る（＝API項目はスクショ不要）。
3. ガードレールの線引き：**作らないのは「自動でテストを実行し機械が合否判定するランナー」**。
   本機能は人が送って人が判定する手動コンソールであり、これは許可（§5.4「実際に回す」・§7 手動工程の系統）。

## 理由
- §5.4 の「実際に回して壊れを見せる」、§7 の手動テスト工程に正しく乗る。判定が人＝オラクル原則も保つ。
- サーバ側実行により CORS に縛られず、localhost/社内ステージングの自分のAPIに届く。

## 捨てた選択肢とその理由
- **自動アサーションで合否を機械判定**: ガードレール（循環参照・自動ランナー）に逆戻り。人判定に限定。
- **ブラウザ(クライアント)から送信**: CORS で内部APIに届かない。サーバ側実行にする。
- **スクショ廃止**: UI確認には不可欠。廃止せず、API項目で送受信証跡に置き換える棲み分け。

## 影響・前提（後で覆すとき確認すべきこと）
- **SSRF/送信先**: サーバ側から任意URLへ送る。ローカル/自ホスト単一ユーザー前提なら自分の送信なので可。
  ホスト共有時は送信先制限・許可リスト等が必要（その時に対応）。
- レスポンス本文は 64KB で切り詰めて保存。タイムアウト 20s。
- Excel エクスポートのテキスト証跡（送受信）反映は今後の調整（現状は画像のみ埋め込み、テキストはアプリ内で確認）。
