# 0016. 種別(track)で「正常系」「手動」「取込」を区別 ＋ JSONインポート — これ一本で対応分の試験項目を網羅

- 日付: 2026-06-28
- ステータス: 採用

## 背景 / 何を決めるか
- これまでテスト項目は **オラクル質問**（リスク/意図の確認 → 人が ✓/✗）からのみ生まれていた。
- だが「ソースから分かる正常系（現状の挙動）」も試験項目として要る。**対応分の試験項目をこのツール一本で網羅**したい。
- さらに、人が **手動**で項目を足したい／実装者が **JSON で一括取り込み**したいという要求。
- これらが混ざると由来が分からなくなるので、**種別(track)で判別**できるようにする。

## 決定
1. **§6.3 アンチミラーの適用範囲を明確化**：アンチミラー（AIが自分の出力を採点する循環参照の回避）は
   **「質問(オラクル)」に効かせる**ものであって、**「テスト項目」そのものには効かせない**。
   - 正常系＝**現状固定（回帰）**であって correctness の主張ではない。正しさは従来どおり **人が ✗（corrected）** で表明する。
   - これにより「全挙動リスト → チェックリスト化（§6.5）」が強化される（オラクルが穴を、正常系が土台を埋める）。
2. **種別(track) を導入**：`records.track ∈ {oracle, normal, manual, imported}`（既定 `oracle`）。
   - `oracle`：従来のオラクル質問由来。`normal`：観測から生成した回帰項目。`manual`：人が手入力。`imported`：JSON取込。
   - 一覧・項目詳細・Excel(「由来」列) に種別バッジを表示。
3. **正常系の生成**：`docs/prompts/normal-gen.md`（単一の真実源）で、観測インベントリ＋AI分析ナレッジから
   `{anchor,title,given,when,then}` の配列を生成 → `track:normal` の候補として並べる（**自動採用しない**）。
   - 候補からは「正常系を全部採用（N）」ボタンで一括採用、または個別に採否。回帰テストは生成済みなので採用フラグのみ。
4. **手動追加**：タイトル必須＋given/when/then/anchor/kind/risk を手入力。`track:manual`・即採用。
5. **JSONインポート**：`ImportItem[]`（title必須、他は任意・既定あり）を貼って一括取込。`track:imported`・即採用。

## 理由
- オラクル（未知のリスク/意図）と正常系（既知の現状）は**別の穴**を埋める。片方だけでは網羅にならない。
- 正常系を「候補に出す＋全部採用」にしたのは、**人が一目で確認してから台帳に載せる**ため（✓スルー対策と整合）。
- track があれば、後で「オラクル由来だけ」「実装者取込だけ」を絞り込み・集計でき、由来の説明責任も保てる。

## 捨てた選択肢とその理由
- **正常系を自動採用**：レビューなしで台帳が膨らみ、✓スルー（無批判承認）を誘発する。候補止まりにした。
- **アンチミラーを正常系にも適用してフィルタ**：正常系は correctness を主張しないので適用対象外。混同すると土台が消える。
- **種別を持たず観測元で推測**：手動/取込は観測が無く判別不能。明示フィールドにした。

## 影響・前提（後で覆すとき確認すべきこと）
- `records` に `track TEXT NOT NULL DEFAULT 'oracle'` を追加（冪等 ALTER ＋ 既存行は既定 `oracle`）。**非破壊**で移行済み。
- `manual`/`imported` は観測(observation)を持たないため、`codeRef.path=null`・`anchor` 既定値などダミーで埋める。
- 正常系は「現状の挙動の固定」。**バグの発見は人が ✗ を選ぶ**従来フローのまま（正常系生成はそれを置き換えない）。
