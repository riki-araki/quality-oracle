# 0017. テスト項目に優先度(priority)を追加 ＋ サイドバーの開閉

- 日付: 2026-06-28
- ステータス: 採用

## 背景 / 何を決めるか
- テスト項目に「どれから試験するか」の**優先度**が欲しい（運用で実施順を決めるため）。
- 既存の `risk`（金/データ/認証/不可逆/重大/その他）は**危険の種別（category）**であって、
  実施順の序列（ordinal）ではない。両者を混同せず別軸として持たせる。
- サイドバーで Project と課題が見分けにくい → **Project 単位で開閉**できるようにする。

## 決定
1. **優先度フィールド `priority ∈ {high, medium, low}`（高/中/低）** を `records` に追加。
   - **既定はリスクから導出**（`priorityFromRisk`）: 金/認証/不可逆/重大=高, データ=中, その他=低。
   - **人が項目詳細で変更可**（`setPriorityAction`）。risk とは独立に上書きできる。
2. **並び順に反映**：一覧（DB `ORDER BY` ＋ `sortForReview`）で「未決 → 優先度(高>中>低) → リスク順」。
3. **表示**：一覧テーブルに「優先」列、項目詳細にバッジ＋高/中/低トグル、**Excel に「優先」列**。
4. **サイドバーを開閉式に**（`<details>`・アクティブな Project は既定で開く・課題数/採用数バッジ）。
   ※ピュアな UI（クライアントJS不要）。decisions 不要レベルだが本判断にまとめて記録。

## 理由
- risk は「なぜ危ないか」、priority は「いつ試験するか」。観点が違うので別フィールドが正しい。
- 既定をリスク導出にすることで、全項目を手で付け直す手間なく妥当な初期序列が出る（人は例外だけ直す＝§6.7の思想）。
- 開閉式サイドバーは Project が増えても一覧性を保つ（視認性の改善要望に対応）。

## 捨てた選択肢とその理由
- **risk を優先度として流用**：category と ordinal の混同。「moneyだが今は試験しない」等が表現できない。
- **優先度を自由数値(1..n)**：粒度過剰で運用が重い。高/中/低の3段で十分。
- **サイドバーをクライアント状態で開閉**：状態管理・JS が増える。`<details>` で十分（アクティブを既定オープン）。

## 影響・前提（後で覆すとき確認すべきこと）
- `records.priority TEXT NOT NULL DEFAULT 'medium'` を追加。**列を新規追加した時だけ** risk から一括バックフィル
  （`migrate()` 内で ALTER 成功＝新規列と判定）。以後は人の編集値を保持（再起動で上書きしない）。**非破壊**で移行済み。
- 既存DBで検証: 137件を risk→priority に導出（money/auth/irreversible/critical=高48, data=中41, other=低48）、証跡無傷。
- 新規レコード（オラクル/正常系/手動/取込）も生成時に priority を設定（オラクル/手動=risk導出, 正常系=低）。
